## 1. What this file validates

This is a **behavioral portability audit** of `MEMORY_PROTOCOL.md` (v2.6) — the contract's Design-for-Portability claim in its own Portability section:

> "Be precise about what that claim actually means: this is design-for portability, not verified portability. As of this version, this protocol has been exercised by Claude-based agents only. Nothing here has been run against Codex, Gemini CLI, OpenCode, Cursor, or a local model... A different implementation should pass the same adversarial regression suite (`tests/`) before its portability is called anything more than intended."

The test target is the protocol's **behavioral contract** (the eight operations, Job dependency policy, contradiction classification, candidate promotion test, health-check honesty, security boundary), never a tool's UI or command syntax. Two guardrails from the ask:

- **Design ≠ portability.** "The protocol doesn't mention Claude-specific APIs" is not evidence of portability. Only a captured run is evidence.
- **The security boundary is host-model-dependent** (protocol, Trust & Enforcement Boundary: "How reliably a given AI separates 'data I'm reading' from 'instructions I follow' is a property of that model, not of this document"). Every environment judged here is judged on what that environment's *actual* model did, not on the protocol prose.

Phase boundary note: this file records measurement only. Any recommendation that touches protocol text ships separately and only after this matrix has real per-cell evidence.

## 6a. Harness bugs found and fixed (test infrastructure, not the protocol)

Three real bugs in `run-battery.ps1` as OpenCode originally wrote it — found by actually trying to run it, which is exactly why "the design looks right" is never treated as evidence in this file either. None of these touch `MEMORY_PROTOCOL.md` or any protocol behavior; all three are fixed in the harness script only.

1. **Wrong root path.** `$root = Join-Path (Split-Path $PSScriptRoot -Parent) 'claude'` went up one directory too many, so every run resolved to a nonexistent `work/` dir and silently `SKIP`ped. Fixed to `Join-Path $PSScriptRoot 'claude'`.
2. **Case-insensitive variable collision.** PowerShell variable names are case-insensitive, so the script's local `$runs = @(...)` (the 10 run definitions) silently clobbered the `-Runs` filter parameter bound to `$Runs` — the exact same variable. Every `-Runs cl0X` invocation was therefore ignored and the full default battery ran instead, unfiltered, with no error. Diagnosed with an isolated repro (identical filter logic worked standalone but failed inside the real script — the tell). Fixed by renaming the local array to `$allRuns`.
3. **`-ArgumentList` mangled prompts with apostrophes or embedded quotes.** `Start-Process -ArgumentList` rejoins an array into a single command-line string, and its quoting doesn't survive an apostrophe (`user's`) or an embedded double-quoted phrase (`"We got a new dog…"`) — CL-02/03/09/10's prompts silently arrived empty or truncated, and CL-04's arrived corrupted enough that the model never saw the actual instruction (0-1 tool calls, no engagement, in every affected run). **Caught by CL-03's own output**, not by inspecting the harness: the model explicitly said *"your message might've gotten cut off — just came through as 'What.'"* — direct evidence of corrupted input, not an inference. Fixed by writing each prompt to a UTF8 file and piping it via stdin (`Get-Content -Raw | & $claude -p --input-format text …`), which needs no argument-list quoting at all. Re-validated with a targeted smoke test on the two worst-case prompts (apostrophe + embedded quotes) before trusting the fix for the full battery.

## 8. Known blockers and confounds

1. **Claude account spend limit — RESOLVED.** Was blocking all Claude-family runs (org-level `disabled until`, `api_error_status:429`). Cleared later the same day (2026-08-29 evening); the full CL-01..CL-10 battery ran successfully after. No longer a blocker.
2. **SessionStart hook contamination — VALIDATED, neutralization confirmed working.** This box's Claude Code fires a global `SessionStart:startup` hook (`session-context.sh`, registered in the **user** settings source) that injects the **real** vault's VAULT-INDEX into the fixture session's context (observed in EV-004). **Chosen lever:** `--setting-sources project` on every battery invocation, dropping the `user` source. **Proven, not assumed:** EV-008 inspected `cl01-base.log` directly — zero `session_start` events, zero `OneDrive` (real-vault path) strings anywhere in the log. Every subsequent battery run used the same flag. Stated trade-off still holds: this also drops the machine's real `UserPromptSubmit`/`Stop` hooks, which is correct for measuring the protocol contract in isolation.
3. **`run-battery.ps1` had 3 real bugs, now fixed.** See §6a — a wrong root path, a case-insensitive `$Runs`/`$runs` variable collision that silently defeated the `-Runs` filter, and an `-ArgumentList` quoting bug that corrupted any prompt with an apostrophe or embedded quote. All three were caught by actually running the harness and reading its output for real, not by re-reading the script. The corrected harness is what produced every `VERIFIED ON` cell in §5.
4. **No `codex` binary despite a populated `~/.codex`.** Earlier install left state (auth/sessions/config) but no discoverable executable. Either the binary lives somewhere unsearched, or the environment was removed. Do not infer testability from the state directory. Still unresolved.
5. **No local-LLM runtime on this box.** Nothing to point at the fixture vault yet; category-6/7 probing of a local model remains future work. Still unresolved.
6. **Gemini CLI, Cursor — not installed.** Unchanged from the first pass; no new information.
